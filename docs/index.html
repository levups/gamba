Gamba

PDFs laid out for you.Prawn code runs on it too, faster.

Gamba is a Ruby library that writes PDF files: invoices, reports, labels. You describe stacks, rows, tables, headers and footers; it measures them, places them, breaks pages where a reader expects, and tags the result for screen readers. It also runs code written for Prawn, the PDF library most Ruby apps use, and for prawn-table and prawn-svg, unchanged: the same pages, faster and in lighter files. An application moves to the native API one block at a time.

gem "gamba"

Every measurement, and how to reproduce it

Why

Prawn draws good pages, but its caller computes the layout: a cursor moved by hand, columns placed in points, the room left on a page measured before each heading. What a document needs beyond drawing, such as a structure for screen readers, has no place in that API. And it is slow: line breaking rebuilds its regular expressions for every line, every number is formatted then patched, and TrueType fonts are read again for each document.

Gamba has an API of its own, where layout is described and every box says what it is. Underneath, it rewrites Prawn’s engine and keeps its Ruby API and its pages, so existing code runs unchanged, faster, and adopts the native API one block at a time.

What changes

Layout described, not computed

Stacks, rows, grids, tables with named columns, headers and footers that know their page. Each box is measured before it is drawn, and pages break between lines, never leaving one alone.

Gamba’s own API

Adopted one block at a time

In a Prawn document, gamba { |document| ... } draws native boxes at the cursor: the rest of the document does not change, and its PDF stays the same byte for byte.

Migration

One gem instead of three

pdf.table and pdf.svg work without prawn-table or prawn-svg; require "prawn/table" and require "prawn-svg" keep working.

Installation

Lighter files, same pixels

Every PDF is written as PDF 1.5: compressed streams, the other objects packed in one compressed object stream, a cross-reference stream. Identical images are embedded once.

Output

Fonts parsed once per process

A TrueType or OpenType font is read once, frozen and shared by every document and thread, until its file changes. Gamba.eager_load! loads it all before a server forks.

Fonts

PDF/UA, PDF/A-3 and Factur-X

pdf: :ua tags a native document for screen readers from its boxes’ roles; pdf_a: true writes a PDF/A-3b document; factur_x embeds the invoice XML your invoicing system produced.

PDF/A, PDF/UA and Factur-X

Prawn’s bugs, fixed and declared

Each fix is proven by a specification and listed with the exact differences the oracle reports. Everything else matches Prawn.

Compatibility

Safe with files users send

An uploaded logo, font or PDF cannot hang the server or fill its memory: a damaged one renders or raises an error Gamba names. SVG images fetch nothing from the web unless asked to.

Files from users

Same pages

An oracle renders every example of Prawn’s and prawn-table’s manuals and every sample SVG of prawn-svg with Prawn 2.5, prawn-table 0.2.2 and prawn-svg 0.40.4, and with Gamba, each in its own process. It compares their pages, their text and its positions to 0.01 pt, their pixels at 150 dpi in MuPDF and in Poppler, their validity and their weight. A seeded fuzzer writes random documents and compares them the same way.

Quick start

Gemfile

gem "gamba" # instead of prawn, prawn-table and prawn-svg

Your Prawn code, unchanged

Prawn::Document.generate("hello.pdf") do
  text "Hello, World!"
  table [%w[SKU Qty], %w[A-1 2]]
end

Gamba’s own API

Gamba.document do |document|
  document.footer { |footer, page| footer.text "Page #{page.number} of #{page.total}" }
  document.text "Hello, World!", role: :h1
  document.table([{sku: "A-1", quantity: 2}], columns: {sku: {title: "SKU"}, quantity: {title: "Qty"}})
end.write("hello.pdf")
